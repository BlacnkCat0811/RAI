## Reading

- S60 `ack_total_ms` P50 4098 ms / P95 5254 ms. The P06 target is P95 <= 1000 ms, so P06 **fails** by roughly 5x.
- Composition of the P50 (ms): json_decode 1801.5 + import_transaction 1973.4 (sample_writes 703.9, association_writes 548.1, dirty_job 145.0, receipt 137.9, routes 107.4, identity_checks 103.3, commit 10.6) + semantic_validation 178.5 + ack_write 0.1.
- The single largest item is strict JSON decoding (1801 ms for 4.1 MB), then the two multi-row write statements.
- Iteration 1 failed with `database_statement_timeout_or_cancel`; the S240 profile could not be measured at all because the 26,382-sample import trips a timeout. Both are recorded as blockers, not as slowness.
- The first iterations of a fresh cluster show `identity_checks` at 12–18 s (cold caches / plan choice); the steady state is ~100 ms. The measurement therefore excludes warmups but keeps iteration 0 in the sample, which is why `max` is far above P95.
