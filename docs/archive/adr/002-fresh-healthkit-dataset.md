# ADR-002：新数据集首次从手机导入历史，不迁移旧数据

状态：已接受，2026-10-27（Asia/Shanghai）。依据用户明确要求：“不迁移旧数据，开发完成部署后，直接手机重新同步导入历史健康数据”。

## 决策与范围

新工程使用全新的 PostgreSQL 数据集、dataset epoch、设备凭证和采集器身份。**不实现或执行本次上线所需的旧 SQLite exporter/importer，不接续旧服务端数据，也不复用旧协议的回执／anchor 作为新数据集已交付证明。** 原始架构方案保留原文；本决策覆盖其中 P6 旧数据迁移与 P8 迁移接续部分，不改变上传事务、删除和增量不变量。

发布后的新原生 iOS 客户端，针对新 dataset/collector/type/queryFingerprint 命名空间建立独立耐久 outbox。各类型首次以空 anchor 查询手机当前可读的历史，按有界页、不可变文件和连续批次逐步上传，不把全历史拼成一个大文件；页文件和 SQLite 状态耐久保存后才能推进 captured，连续页的全部批次取得 committed 原回执后才能推进 delivered。

这只发生在用户明确选择的新数据集首次导入。其后的断网、后台恢复、401、超时、下发游标失效或分析失败均不得清 anchor、删除未确认 outbox、改批次身份或重导全部历史。旧客户端任务和本地状态不在新客户端中自动删除；不同 dataset 的凭证、回执、文件和游标必须严格隔离，旧 envelope 不能提交到新 dataset。

## 能恢复的内容与边界

首次读取只覆盖手机当前保有且 HealthKit 允许读取的对象；不能据此保证手机缺失、已删除或不可见的历史能恢复。空查询或权限变化不产生删除。旧服务端的人工修改、训练计划／执行记录、模型激活状态、旧回执及旧删除记录不在本次接续范围；手机健康事实不会重建这些服务端专属状态。

P0 的功能、API 与算法语义盘点仍需完成，以便新系统保留目标产品行为；“不迁移旧数据”不能代替 P5 算法对照、P7 真机与恢复验收。首次健康历史导入采用正常增量管线的有界处理，不额外触发全库摘要、备份、换库或无边界全量分析。

## 发布与回退

用户表达的是开发和部署完成后的导入路径；当前尚未完成开发、真机和部署验收，不在这一工作包自动部署或切换入口。部署操作继续遵循 [工程约定](../../AGENTS.md)。旧目录和旧生产服务保持原状，不改写或清空旧库。

新库开始接收数据后优先向前修复或回退兼容的 Go 镜像。旧服务无法看见新库写入，不能把切回旧入口当作无损数据回滚。备份恢复和 epoch／流缺口恢复仍须独立验收；取消旧库迁移并未取消 PostgreSQL 灾难恢复要求。

当前该文档只是已接受的实施决策；新 iOS、首次导入、后台恢复和发布流程尚未通过验收。真实证据见 [实施记录](../IMPLEMENTATION.md)。
